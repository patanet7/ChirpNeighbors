# Coast live oak module wind proof

Two image-generation calls produced one rigid wood scaffold and one four-part leafy branch sheet. The exact existing IDs are `coast-live-oak-wood` and `coast-live-oak-foliage`, species family `quercus_agrifolia`, variant `depth06_modules_v1`. The four extracted modules are layer slots inside the single foliage asset. No new primary species or four new foliage asset IDs are created.

**Whole-tree healthy-canopy admission is on HOLD.** The visible assembly has four small leafy tufts on a sparse, pruned-looking scaffold. It demonstrates source separation, attachment and offline motion; it is not a complete normal healthy coast live oak placeable. The wood and leaf-bearing modules are actual source candidates. Species anatomy, full-canopy shape, owner acceptance and runtime admission remain unverified. The older Engelmann oak attachment HOLD remains unchanged.

## Art and registration

The actual existing project oak wood/foliage pixels and canonical manifest were inspected. Only those owned project images conditioned the new wood call; the new wood plus the existing project foliage conditioned the module call. Another-species style image was inspected during initial discovery but was not a generation input. No external reference image, public style reference or other product reference was used. Source hashes, exact prompts and input lineage are retained. Applicable generation-service/project terms apply; no open license is asserted.

The wood request was 1024 square, but the returned original is 1254 square. It is preserved byte-for-byte and translated[400,400] onto a 2048 square assembly canvas, without scaling or redrawing. Four real, opaque, connected near-tip points were inspected at source coordinates A[174,413], B[556,192], C[943,276], D[1178,586]. A small additional nub on the wood stays static; no hidden geometry is claimed to have been recovered.

The generated 1536×1024 module sheet contains four complete airy leaf-bearing branches. Their bases are thicker cut-end stubs, rather than ideal narrow living tapers. All four originals are extracted by lossless rectangular crops; no bark/leaf artwork is code-painted, recolored, inpainted or erased. Natural gaps have real alpha, with partial-alpha edge/residual pixels retained.

Each module's visible base and forward direction were manually selected, then uniformly scaled and rotated to the corresponding actual bough direction. Exact crop boxes, base coordinates, scales, angles and destination points are in `reports/module-transforms.json`. The attachment point was refined 20–30 source pixels inboard on the same near-terminal bough so that fixed wood can cover the generated cut face. Final wood-source overlap points are A[191,427], B[544,216], C[920,292], D[1157,603]. This is an explicit layered overlap method, not a claim that cut faces disappeared from the source art. Wood renders above modules at the joints. Actual wood/module/assembly triptychs were inspected for floating gaps and gross attachment failure. The joins look continuous in those views; exact anatomy and occlusion masks are not certified. Manual source picks carry an assumed±4 px tolerance, not a measured confidence interval.

## Actual offline deformation

`python render_motion.py` requires Pillow and NumPy. It operates on packaged source sprites and relative metadata paths, with no app connection. Rest placement uses inverse affine nearest-neighbor sampling, aligning the selected source base pixel center exactly with its destination center. It preserves an immutable original wood source and a fixed translated wood layer.

The animated module deformation is a radius-dependent twist around its own fixed attachment. Its inverse map samples existing pixels. Motion weight is 0 within 48 assembly pixels of the base, smoothly rises to 0.35 between 48 and 100 px, then to 1 by 260 px. These are artist branch-lever/distal-foliage control envelopes based on distance. They are **not** semantic branch/leaf segmentation, botanical stiffness, calibrated wind speed or physics. The entire original rigid wood/root weight is 0. No procedural opacity/color flicker is added. There is no animated ground, planted understory or background.

Mild/heavy drives use 2°/6° base amplitudes, per-module reductions and a small second harmonic. Each drive has 32 intervals at 80 ms, nominal period 2560 ms. A duplicate closure pose is appended, so the encoded 33-frame GIF lasts 2640 ms with an 80 ms closure hold. The animation loop has exact first/last equality; the closure hold is disclosed rather than claimed as continuous-time velocity validation. Only six 512 px PNG poses per mode are retained; full assembly-sized sequences are regenerated in memory.

Both GIFs use the same fixed 256-color palette, trained once on rest colors. No per-frame quantization palette is generated. Each GIF is decoded again: actual frame count, distinct RGB hashes, exact encode/decode RGB agreement, first/last equality and unchanged visible wood/root are checked. All four 48 px base cores are byte-identical to rest in every rendered frame. Attachment coordinates and source wood hashes are logged per frame. Every module patch edge and assembly extent is checked for clipping.

The validation reports 33 decoded frames and 31 unique RGB hashes per mode; repeated rest poses account for the duplicates. All 12015 tested exposed rigid-wood display pixels stay unchanged, and the root region has one identical decoded RGB hash throughout. Base drift is 0 by the implemented constraint. These numerical constraints do not prove botanical attachment or a complete tree rig. Source/crop and manual alignment uncertainty remain separate.

## Review and states

Worker review covered proper light/dark source composites, four actual base crops, four wood/module/joint triptychs, the rest assembly and six actually decoded GIF keyframes for each mode. These are visual pose/contact checks; continuous motion playback was not independently observed by the model. Parent inspected the decoded six-pose contacts and found continuous attachments and fixed wood, while placing normal healthy whole-canopy admission on HOLD because of the sparse/pruned appearance.

Actual new art is rigid authoring wood and healthy leaf-bearing branch modules only. The bare authoring scaffold is not a winter state. Dry/stress foliage, normal seasonal turnover, wet appearance, acorns/catkins and a complete normal healthy crown are missing art needs. No whole-crown orange autumn or snow default is implied. The two actual GIFs are offline previews, not two runtime-admitted animation clips. Root footprint, perches/collision, weather interaction, wind response and bird behavior in an application remain unimplemented.
