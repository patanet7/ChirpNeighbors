## Contracts, storage, authentication and privacy

**CSA-01.** The common directory/database helpers accepted a configured private data root inside `public` or `build/client`. The app process can serve its own mode-0700 directory and mode-0600 files; those modes do not establish an HTTP boundary. Adapter-node indexes existing client assets before application hooks. A lazy database-init check therefore cannot protect retained static files after restart.

Source: UI [private-files.ts](https://github.com/patanet7/birdsong-yard-sprites/blob/1c10ba9194b4fe961ab201b71e26988be0b331dd/src/lib/server/storage/private-files.ts) at line 18; `runtime.ts:49`, `auth/config.ts:110`, `analytics/runtime.ts:16`; `scripts/config/svelte.ts:6` selects `public`. Reproduction copied the built app into a temporary directory, created a synthetic SQLite file under `build/client` using the real helpers, started the copy, and fetched that file without a cookie. Response: **200**, **8,192 bytes**, SQLite header and synthetic marker present, despite **0700/0600** modes. No owner data was read. Validation must precede writes and listening and account for prospective real paths/symlink aliases; rejected configuration must not move/delete operator data.

**CSA-02.** `package.json:10` enabled fixture auth and `--host 0.0.0.0`; `vite.config.ts:8` repeated that default. The real `/auth/dev` route chooses Alice/Bob when development and opt-in checks pass. Same-origin form validation is CSRF protection, not access control for another client already able to reach the origin. Persisted test identities can later contain imported private material. This was established by source inspection; no wildcard/external reproduction was started. Production account authentication was not found bypassed.

**CSA-03.** [hooks.server.ts](https://github.com/patanet7/birdsong-yard-sprites/blob/1c10ba9194b4fe961ab201b71e26988be0b331dd/src/hooks.server.ts) at lines 121–123 released admission after returning the Response object, before its stream completed. The declared read limits were 16 per owner / 64 globally (`operations/request-budget.ts:13`); playback retained its blob until completion/error/cancel (`recordings/service.ts:193`, `:241`–`:267`). A real-hook Vite SSR reproduction held synthetic response bodies: **20 responses returned 200 with all 20 streams still open**, despite the owner ceiling of 16. Cancellation closed all 20. OS descriptor exhaustion was deliberately not attempted. A repair must release once on body completion/error/cancel and preserve blob cancellation/deletion fences, including HEAD and no-body failures.

Focused existing verification: **219 tests / 12 files passed**, covering auth configuration/service/session binding/response, private modes/symlinks, database preflight, persistence/isolation, safe sharing, consented analytics, bounded readers and budgets. These passing tests did not cover the reproduced missing cases. Inspection confirmed server-derived owners, session replacement fences, frozen sanitized shares, owner predicates/prepared statements, chunk-level deletion rechecks and explicit recovery freshness limits. It was not exhaustive route/library or multi-host certification.

## Jobs, providers and asset lifecycle

**JA-01.** In `animation-planning@2`, suspend the first discovery page, cancel its job, then return that page with a next cursor. A second adapter invocation occurred with `{status: "cancelled", signalAborted: false, cursor: "second-page"}`. The durable job stayed cancelled and committed no output. Network calls: **zero**; the adapter was a stub. Existing bounds still limited discovery to three pages/eight requests/fifteen seconds.

Source: [runner.ts](https://github.com/patanet7/birdsong-yard-sprites/blob/1c10ba9194b4fe961ab201b71e26988be0b331dd/src/lib/server/pipeline/runner.ts) creates the per-advance signal and persisted cancellation callback at lines 61–67; repository cancellation updates job/run/lease state at `repository.ts:606`; `asset-pipeline/animation-planning-v2.ts:59` forwards only the signal; `reference-discovery/service.ts:93`–`:104` checks only that signal before another search. Cooperative cancellation must reach actual page/retry boundaries; cancellation cannot undo a request already sent.

**JA-02.** Archive one valid package, then admit 512 newer fixture jobs. **513 jobs were accepted but only 512 lifecycle entries returned**; the oldest archived target disappeared and `referenceScan` was `incomplete`. Bytes and pins survived, and an ID-aware caller could still use the guarded API. The UI rendered only returned entries, so restore was unreachable through normal controls.

Source: `pipeline/repository.ts:205` admits history independently of the limit; [assets/lifecycle.ts](https://github.com/patanet7/birdsong-yard-sprites/blob/1c10ba9194b4fe961ab201b71e26988be0b331dd/src/lib/server/assets/lifecycle.ts) at lines 262–267 bounds graph rows, then line 360 derives visible entries from that graph; `AssetLifecycle.svelte:201`/`:239` has no older-page retrieval. The separate **32 MB** source-metadata branch at line 257 omits all package nodes; that branch was inspected, not executed in this reproduction. Keep the conservative dependency scan and separate bounded owner-visible history retrieval; increasing the whole-graph cap postpones the defect.

Focused existing verification: **91 tests / 5 files passed** (`pipeline`, `completion-authority`, `reference-generation`, `assets/resolve`, `assets/lifecycle`), with one Vitest worker. Both isolated reproductions asserted the reported defect. Inspection confirmed single live leases, bounded retry/review pauses, late-output fencing, completion authority under the write lock, exact private reference/manifest pins and default-deny real production catalog promotion. The only generation adapter was a non-renderable local diagnostic fixture. No model or genuine species artwork was evaluated.

## Renderer, simulation and game behavior

**RG-001.** [renderer.ts](https://github.com/patanet7/birdsong-yard-sprites/blob/1c10ba9194b4fe961ab201b71e26988be0b331dd/src/lib/engine/renderer.ts) at line 854 destroyed the remaining graph with `{children: true}`. Installed Pixi 8.22.0 requires `context: true` when an options object is provided to dispose a Graphics-owned context; bird views already explicitly release their own contexts/leases. An actual Chromium/Pixi probe captured **18 contexts** before teardown: three bird contexts were destroyed, while **15 scenery/object/visitor/weather contexts retained instructions and one GPU-data entry each**. Counters nevertheless reported zero views/graphics/display objects/canvas pixels. A second renderer stayed usable, with no page errors. Deliberately retained probe references establish incomplete deterministic disposal, not post-GC heap or VRAM byte measurements.

The mocked resource tests and browser checks of counters/removed canvases did not inspect those contexts. The repair must preserve `releaseGlobalResources: false`, shared lease ownership and another live renderer. Actual-context assertions across normal teardown/context loss/repeated mounts are required.

**RG-002.** The [retained performance record](../delivery/renderer-performance-20261010.md) measured Vite development mode with SwiftShader. Synchronous `app.render` wrapper times improved, but owner-component 96-resident p95 was **166.6 → 166.7 ms** and oversized DPR2 p95 was **416.7 → 449.9 ms** in the original comparison. The balanced follow-up established neither a consistent cache tail improvement nor equivalence. Production-build and physical-GPU behavior remained unmeasured. The 150 ms elapsed-delta clamp can reduce simulated ticks during slow real-rAF trials; fixed-ticker parity is separate proof. Keep visible/waiting/deferred counts, actual ticks, CPU work and frame pacing distinct. No blanket batching/reactivity rewrite follows from these observations.

**RG-003.** Generic species-color fixture frames and illustrative tuning support the nine engine actions. Missing sleep/play/nest clips resolve to labeled still idle poses. This does not supply reviewed anatomy, authored species-correct actions, approved concepts or final fidelity. Retain frame/pose/provenance validation and normal/reduced-motion/Pixi/SVG review as acceptance for actual artwork, not synthetic routine-test counts.

**RG-004.** `YardScene.svelte:277` tears down failed WebGL and retains environment/time; SVG rebuilds actors from `createSimulation` at line 213 and samples idle/sleep. Its one-shot initialization prevents in-place WebGL recovery until remount. Static reconstruction is the current documented contract, not a newly established parity bug. Exact actor/claim continuity is a future product choice.

Focused existing verification: **123 tests / 10 files passed** (simulation, routines, sleep, layers, shape occupancy, renderer resources, scene budget, geometry cache, environment policy, visits). The actual-Pixi disposal probe reproduced RG-001. Earlier resource **18/18**, renderer correctness **251/251**, environment **47/47**, routines **19/19** reports were inspected, not rerun or added to fresh totals. Simulation remains independent of storage/network; placement uses CAS and centralized occupancy reconciliation. The 96 presentation candidates and geometry/backing limits do not bound all saved controls/registries, parsing, font atlases, heap or VRAM. Free-flight corridors are not obstacle-aware silhouette avoidance.

## Runtime, developer experience and CI

**RDX-001/002/005.** Fixture wildcard binding duplicates CSA-02. The UI and separate unauthenticated headless receiver both default to port 8080 (`package.json:10`; main `backend-inference/app/main.py:49`/`:96`). The app needs one Node process and private SQLite/media storage; ordinary startup must not silently start the receiver, model service or missing worker. There were no supported ownership/status/stop commands. Existing browser helpers demonstrate owned child cleanup; liveness is separate from storage/auth readiness. Never terminate an unrelated port occupant or trust a stale PID file as identity. Actual origins must follow the bound port, and a remote localhost URL is not a user-accessible preview.

**RDX-003.** The former aggregate instructions installed Playwright alone, omitting Pillow, and passed the core interpreter for intake by default even though its lock excludes NumPy/websockets/coverage. The [corrected command](../delivery/quality.md) selects core, browser, ONNX and intake environments explicitly. Document repair does not establish a new clean-platform installation pass.

**RDX-004.** The reviewed hosted workflow omitted npm `test:ontology`, `test:asset-retention`, `test:shared-catalog` and `test:environment`; standalone animation-planning/reference-admission/reference-recovery/audio-lifecycle scripts were also absent from its list. Some require paired/service dependencies and cannot simply be labeled UI-only. Local aggregate execution and per-repository hosted checks are different evidence. At review, the UI job failed twice before recorded steps; permitted logs did not establish the cause. Neither the omissions nor lack of a required-check rule turn that into a hosted pass or a diagnosed account/billing failure.

**RDX-006.** The UI full-delivery table still said ESP32 integration was absent while a later checkbox recorded completion; EN-010's original fields said local/unpublished while its later paragraph recorded both engine merges. Historical checklists must preserve exact past evidence and link current status to PB/EN. This documentation change corrects main-repository navigation/current fields; UI reconciliation belongs to the paired integration.

Runtime review was source-only: no install, process action or new test run. Recommended composition uses [mise tasks](https://mise.jdx.dev/tasks/) for tools and ordered commands and typed app-owned lifecycle code for readiness/ownership. Its [configuration reference](https://mise.jdx.dev/tasks/task-configuration.html) distinguishes parallel dependencies from sequence; experimental daemon integration is unnecessary for this one-process slice. [Vite server options](https://vite.dev/config/server-options.html) distinguish wildcard hosts and strict collision failure. No task cache should contain credentials, private media or runtime control state.
