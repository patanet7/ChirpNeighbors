## Three corrective slices for dispatch

### CN-AUD-001 — Put the normal saved yard and workbenches on one runtime contract

Start with behavior + one actual saved bath/fountain and physical surface model. Add a canonical YardRuntime/session owner for saved birds, objects, asset selections, environment, simulation/clock, contact authority, optional physical state and diagnostics. Normal yard and workbench should select/inspect the same actor/object IDs and subsystem contracts. Use current artwork/fixtures; new animation art is not needed to establish wiring. Preserve the garden as an explicit scenario adapter until it consumes that contract.

**Acceptance:** an isolated real-session/API/SQLite/browser test loads two owners with different layouts, enters main yard then workbench and sees identical bird/object/pin/runtime IDs. Selecting a non-Robin actor and a second bath works. Drink requires actual travel/owned wet slot and debits that same object's ledger. Moving/removing it through normal commands cancels stale contact without losing mass. Intended configuration/layout/pins survive reload and stay tenant-scoped; transient simulation-state policy is explicit. A route-level gate fails when normal-yard subsystem configuration is omitted. No synthetic marker or hardcoded demo jay can satisfy the test.

### CN-AUD-002 — Make that runtime reproducible and inspectable

Build one experiment contract consumed by the connected workbench: schema-derived units/defaults/bounds, validated numeric tuning, editable seed, pause/one-tick/N-tick/reset, selected actor/object/slot/route/contact overlays, bounded decision/event/error history, initial state and timestamped input timeline, portable local scenario import/export. For auth/media/catalog, expose safe policy/state/receipt diagnostics and isolated fixtures instead of meaningless physics sliders. Keep image-review packages distinct from simulation scenarios.

**Acceptance:** export a normal-yard experiment, replay it in the workbench at15/30/60Hz and drained stutters, compare complete actor/occupancy/surface/fountain/receipt state. Replay covers rain changes, blocked/dry slots, move/remove/re-add, hidden/reduced-motion holds, stale response and core rejection. Defaults/bounds in UI match schema; invalid edits retain the last valid state. Export contains the exact source/schema/seed/initial state/input timeline and excludes credentials/private media. Actual browser rendering/overlays and effect of each priority dial are observed, not only direct helper calls.

### CN-AUD-003 — Unify weather, surfaces and seasonal rendering on that runtime

Use the saved yard's existing resolved environment as the common input for behavior, wind, surface precipitation/melt and seasonal visuals. Make the seasonal tree a versioned render adapter over a real scene object/asset selection, with explicit decorative versus physical capabilities. Reuse existing numerical/tree/render modules; do not replace them with another scene composition. Manual deterministic weather is a valid first integration scenario; real-provider completion remains separately tracked as CN-AUD-004.

**Acceptance:** normal `/` and its connected workbench show identical object IDs, applied environment/season revision, clock and render diagnostics. A recorded rain→snow→melt scenario changes that same surface ledger and visible geometry while bird shelter/contact rules use the same environment. Moving/removing/re-adding the selected object retains the documented state/mass policy. Layer/season toggles alter paint without inventing supports or dropping water. Source-linked screenshot pairs, exact state/ledger assertions and event traces cover main yard at narrow/wide viewports, holds, reload and recovery. Tests invoke real route/API/storage and actual renderer, not only a synthetic helper. Live weather, physical botany and calibrated art stay open until their own acceptance passes.

The first three slices preserve the existing engines while closing normal-yard behavior/water/rendering and environment/season integration. Provider, device, catalog and art readiness retain separate acceptance evidence; none should be closed by a larger unit-test total.
