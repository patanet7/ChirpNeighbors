## Profile-led implementation choice

The existing renderer clears and reconstructs every rectangle when a resident's sampled frame/pivot changes. Installed Pixi 8.22 then tessellates the changed GraphicsContext. Contexts can be shared without changing the authored geometry or transform path. A renderer-local immutable cache is the first candidate; its default batching policy remains unchanged so the initial comparison measures geometry reuse separately.

The initial five-second instrumented adversarial sample (10 placed views, 3,000 rectangles per frame) recorded roughly 1,537 ms of synchronous application render work and 746 ms of GC samples. Inclusive stacks include about 1,001 ms in `updateGpuContext`, 903 ms in `buildContextBatches`, 781 ms in `syncViews` and 743 ms in `drawBird`. These inclusive values overlap and must not be added. Ordinary fixtures also issue many draw calls; their profile is largely idle between callbacks, so high frame intervals alone do not establish a JavaScript bottleneck. This initial matrix used two legacy species IDs outside the current catalog; it remains valid attribution evidence but is not the final matched catalog-fixture comparison. The corrected matrix uses the actual Robin, House Sparrow and Blue Jay IDs. Raw baseline evidence and the complete comparison will be linked after capture.

No quality reduction, new hiding/admission policy, raster replacement or automatic bird rotation is authorized as an implicit optimization. Existing resource bounds, private owner boundaries, deterministic simulation, environment playback and exact asset pins remain acceptance constraints. Existing pixels are technical fixtures, not approved art or biological fidelity evidence.
