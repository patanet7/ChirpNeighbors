# Advisory asset quality evaluation V1

This implemented source boundary carries machine-readable diagnostics for the current bird-manifest path (V2–V6). Other asset families remain unsupported by this source-binding validator; do not invent a bird taxon for them. It does not grant source review, rights, biological/contact approval, runtime admission or a pin change. The report fixes `schemaVersion:1`, `authority:asset-quality-evaluation-v1`, `advisoryOnly:true` and `grantsAdmission:false`. Existing schemas, registry/services and producer records are unchanged. Portable registration and canonical mirrors belong to the integrator; this implementation supplies the source authority and consumer seams.

Additional consumer exports are `assetQualityReviewedContactProofSchema` / `AssetQualityReviewedContactProof`, `CANONICAL_SOURCE_ART_LABEL_REFERENCE_V1`, `ASSET_QUALITY_SOURCE_LABEL_CLASSIFICATIONS_V1` and `retainCanonicalAssetDefectSourceLabel`. These are reference/migration/context seams; register only the report authority.

A binding must come from the existing authenticated owner/source/lifecycle lookup, **never from the submitted report**. Its subject/requirement hashes must already identify immutable verified bytes; this pure module cannot authenticate callers, rehash unprovided files, verify rights or fetch references. Report parsing alone is not current-source binding. Cross-report supersession/repair byte verification and actual review authority remain in the existing pipeline/lifecycle consumer.

Reviewed contact uses `reviewedContactProofs`, not a bare hash allowlist. Each trusted proof carries its evidence `sha256`, exact `subject` (including source/manifest/geometry), exact `requirement` (including support scene/version/object/slot/geometry), and bounded `coverage` entries. Each entry covers the explicitly declared Cartesian product of one `clip`, `frames`, `poseIds` and `contactKinds`, restricted to its source-canvas `region`. A singleton list is exact coverage; wider lists must be explicitly reviewed. Null pose matches only an unspecified pose, not every pose. Null region explicitly covers the full canvas; a bounded region only covers findings entirely inside it. A report targeting the full canvas cannot use a smaller region's proof. Finding applicability must be a subset of one trusted coverage entry with the matching evidence hash. Changing contact/frame/pose/source/requirement/support/geometry invalidates a narrower prior proof even if the hash is reused.

`assetQualityReviewedContactProofSchema` and `AssetQualityReviewedContactProof` describe this consumer context, not another portable report authority or a submitted source of trust. Proofs have at most 32 coverage entries, 256 frames/pose IDs and four existing contact kinds per entry, with unique finite lists and in-canvas regions; a binding admits at most 64 proofs. The existing authenticated consumer must independently verify review provenance, bytes, scope and currency before constructing this context. Submitted proofs/extra binding fields and legacy bare hash lists fail closed. This pure validator checks applicability; it cannot certify that a trusted reviewer actually inspected the declared scope.

## Canonical source labels and migration

The sole source-defect namespace is [`shared-source-art-defect-label-contract` version 1](https://github.com/patanet7/ChirpNeighbors/blob/d104afbaf6949d71d24768a577f4eb9d8ef709c3/docs/art/asset-defect-labels-v1.json), canonical revision `d104afbaf6949d71d24768a577f4eb9d8ef709c3`, file SHA-256 `b78e048b84bff2a99da153c6b3636bb5683b4d0ab015d8b68fa3745b39a56996`. The [reference fixture](../../contracts/fixtures/asset-defect-labels-v1.canonical.json) retains its exact bytes. `CANONICAL_SOURCE_ART_LABEL_REFERENCE_V1` pins that reference; it does not create another source catalog. The ten evaluation rules below are a separate, bounded classification of evaluator findings, never replacement source codes.

`retainCanonicalAssetDefectSourceLabel(originalJson,declaredSha256,applicability)` is an explicit normalized migration seam. It retains the original JSON text exactly in `source.originalRecord`, including scope, grade, finding state, reason, evidence, identity/revision and extra fields. Parsing checks finite/depth-bounded JSON, the catalog's required-field presence and declared label/scope/grade/state vocabularies. It does not assert an existing producer serializer, rewrite original records or convert any source grade/state into evaluation knowledge, verdict, review or admission. Unknown canonical labels/versions, missing records and label/record collisions fail closed. Other unverified legacy label vocabularies remain raw and unclassified unless explicitly mapped.

The retained envelope has `{json,sha256,applicability}`. `unverified` is historical/provisional retention and must stay unclassified; it makes no subject applicability or hash-authenticity claim. `subject-source` requires original `asset_id` and `source_sha256` to match the report's exact asset/source. The binding then requires an independent `sourceRecords:[{sha256,json}]` lookup with the same hash **and exact original text**. The trusted consumer must first verify the UTF-8 record hash and its provenance/revision through existing lifecycle authorities. A submitted digest alone is insufficient; changing text while reusing a hash fails binding. A record whose applicability cannot be established remains unverified, even if its catalog label is known. Variant/revision/evidence payload details remain opaque original data until a verified producer adapter is available.

## Evaluation labels and provenance

Ten categories reuse the reviewed specification: species identity/anatomy, pose/action phase, support/contact, registration/centering, relative scale, palette/style, transparency/noise, temporal stability, technical budgets and runtime adoption. V1 defines one provisional evaluation rule per category. Rule membership only classifies an evaluation; it does not certify the result. New meanings/IDs require a new authority version, preserving V1.

Raw labels are retained byte-for-byte with their optional source-catalog/version pair. A mapping has a known diagnostic rule, `proposed` or `reviewed` status and evidence SHA-256. Reviewed means the **mapping** has a review reference; it is not biological truth or runtime approval. Experiment IDs cannot be substituted for rule IDs. A report rejects category/rule mismatch, conflicting mappings, duplicate IDs, missing references and local supersession cycles. Prior-report references preserve report ID/digest/finding ID; validating the external ancestry graph is a consumer obligation.

The report references existing taxon IDs, nine action/clip names, six `ActorMotion` phases, V6 blink/look names, four existing manifest contact kinds and existing derived slot-ID validation. It adds no species/action/contact/support ontology or lookup database. Requirements are distinct from actual sampled clips: an idle fallback never establishes requested bathing/flight coverage.

Findings bind subject/frame/pose/region, method/tool/code/config and optional model/version/prompt/config, evidence, independent severity/confidence, measurements, repair and review. Regions are **source-canvas pixels**, not world/CSS rectangles; measured values declare their unit separately. Source/RGBA/manifest/geometry/content hashes and optional recipe/support context remain exact references. Model-backed CV/VL judgments are inferred or unknown; mutable/unknown model aliases are not version provenance. The module records pinned declarations but cannot verify provider claims or calibrate a judge.

`observed` is qualitative evidence; `measured` requires finite measurements with units/tolerance; `inferred` preserves judgment and optional confidence; `unknown` cannot claim pass/fail, severity, confidence or measurement. Calibrated confidence requires a calibration evidence hash; ordinal confidence requires a rubric hash. These are reference checks, not evidence-quality certification. Missing contact proof remains held/unmeasured; a contact pass/fail needs exact frame/contact/support/geometry and independently bound reviewed reference, or an explicitly synthetic reference that remains synthetic. Declared contact self-drift is not reviewed anatomical error.

Repairs only describe immutable proposals/results; this module never edits pixels, centers frames, mutates a source/pin or runs CV/VL. None/proposed/applied/rejected states require coherent hashes. Review outcomes require review evidence while always retaining `grantsAdmission:false`. Physical withdrawals and accepted runtime actions still use their existing controllers.

## Bounds and compatibility

Reports are at most 65,536 UTF-8 bytes, 256 findings, 64 evidence references and 16 tools. Individual labels/IDs/arrays/coordinates/measurements are bounded and finite. The explicit mapping adapter admits at most 128 mappings and rejects duplicate source identities. Source regions must fit the exact canvas. Manifest binding supports the existing V2–V6 clip/pose representation, including V6 common attention, and never samples fallback to invent missing coverage.

The existing JSON Schema exporter represents structural bounds. Source refinements additionally enforce reference/category/model/evidence/contact/review/repair/supersession coherence and byte limits. Current manifest/source binding requires the separate validator context and is not expressible by the report schema alone. Integrator golden/property cases must preserve that distinction; do not loosen old authorities to force structural and semantic results to match.

The public [synthetic fixtures](../../contracts/fixtures/asset-quality-evaluation-v1.synthetic.json) contain marker hashes and invented local IDs only: an inferred Crow stride/rest mismatch and unknown bath contact. They are illustrative negative/missing-evidence cases, not real producer evaluations, pixels, admission or the pending Crow ancestry qualification. The canonical source catalog is now pinned as described above; no verified producer serializer or actual regional finding migration was supplied. The actual producer adapter must construct this contract explicitly from its own known records and verified mapping; foreign/unavailable input stays unclassified or rejected.

## Integration handoff

The integrator owns registration/export, shared goldens/property seeds/semantic exceptions and canonical mirrors.
