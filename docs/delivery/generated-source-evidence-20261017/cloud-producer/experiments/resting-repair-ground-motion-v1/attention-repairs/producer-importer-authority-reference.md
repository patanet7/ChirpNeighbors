# Recover project-generated source without inventing rights

The producer owns source facts: exact originals, prompts, generation records, source-frame IDs, derivatives and authored clocks. The consuming importer owns private repository bindings. A producer outside that repository must not invent job IDs, reference pins or review decisions.

The legacy field named `source.license` is also used for an internal owner-authorized private-work policy. It does not require an external copyright license name. Generated work must not be labeled CC0, nor inherit a license from a cited photograph that was never used. The private policy grants no public redistribution or legal clearance. Input image references retain their own provenance and rights; a technical renderer fixture is not a historical generation input or an authorization for one.

## Repaired path

1. Materialize the exact source delivery and verify its index. Decode the supplied final PNGs and compare their PNG/RGBA identities with the proposal; inspect actual pixels before judging appearance.
2. `collectProjectLineage` follows source-frame records, original hashes, exact prompt files and generation receipts. It recovers generated conditioning frames recursively, including declared original variants absent from the active frame bank. Variant RGBA identity is verified. Missing original/input enumeration, unknown image ancestry, changed hashes, cycles or a false generator label stop recovery. Model/seed stay null when unavailable. A factual guide citation is separate from an image input. No new generation, external fetching, geometry or approval is inferred.
3. Retain a `project-generated-evidence` job and review its immutable evidence artifact. The artifact binds the selected archive hash, every recovered original/prompt/generation-record hash, the exact source-frame bytes, an existing reviewed private-policy source pin, and the owner's current private processing request hash. This is retained project history, not independent provider attestation or copyright certification.
4. `recoverProjectCommonInput` resolves that exact approved evidence and existing private policy **in the consuming owner's repository**. It copies the recorded private-use declarations, links their evidence to the new immutable artifact, and resolves the real technical style/pose pins. It fills only missing producer fields; a conflicting declaration or supplied reference is rejected. No new permission, public redistribution, reference-image license, taxonomy or support approval is created. The existing policy must be the owner-authorized private technical study, for the same owner/species, with redistribution disabled.
5. Submit input5, or PNG package command4, through the existing immutable file→source→manifest review path. A V5 package requires its additional generated-evidence pin. Load/repack verifies its owner, review, version/digest, policy dependency and all decoded-frame hashes. Stripping the pin/downgrading a `project-evidence:` declaration is rejected. Neither the recovery proposal nor diagnostic report is an admissible package.

These schemas are generated from the UI's Zod authorities and mirrored in ChirpNeighbors. Older source, command and manifest authorities remain independently exportable. The render data is still manifest6: history is a source dependency, not new pixel geometry. Old servers must upgrade before consuming source4/input5. The existing nine activity names, approved-art requirements and public sharing boundaries do not change.

`node scripts/check-common-intake.ts <private-input.json>` now emits report2. Its four output-use issues belong to the authorized requester/importer policy; seven reference-binding issues belong to the consuming runtime integrator. It separately runs source-declaration checks where shape permits. A structurally nullable evidence ID does not pass the declaration gate. `sourceAdmitted`, `rightsGranted`, `generationInputsAssessed` and `referenceRightsAssessed` remain false: a metadata report cannot certify any of those facts. The old report1 function remains available unchanged.

## Actual Dove and Warbler result

The source bank recovers three historical generation records for Dove and seven for Warbler. Both chains reach the retained unconditioned Dove root. Warbler's style chain passes through generated Sparrow, Scrub-Jay and Finch records. The Finch reference note contains an unused photo candidate; its bytes were not downloaded or inspected according to the retained records, and its license is not used for these generated outputs. Existing-frame look/blink processing made zero new calls or drawings.

Both supplied families go from eleven unresolved fields (four declarations, seven runtime bindings) to zero metadata errors in an isolated copy using its actual pre-existing reviewed private-work policy and owner-local technical references. The real file/source/history/manifest review gates pass, and all six render frames reconstruct supplied RGBA exactly with source pivots and clocks unchanged. Both remain unpinned; the copied yard and live yard are unchanged.

This result is source packaging, not acceptance of new artwork. Warbler blink remains faint. Feet, physical support, anatomy, facing, normal-yard scale, live clarity and browser acceptance remain unreviewed. Browser QA stays stopped. Unknown or external conditioning inputs must retain an explicit missing-evidence/rights blocker; generation does not clear them. No user geometry or new permission paperwork is needed to recover records we already retained. Canonical611 remains partial;622 is not closed.
