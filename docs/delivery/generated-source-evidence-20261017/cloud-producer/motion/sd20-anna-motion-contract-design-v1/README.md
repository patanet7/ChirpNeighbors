# Anna motion contract design — preparation only

Zero image calls, zero new drawings, zero source edits and zero runtime bindings. This technical companion extends the existing `anna-source-action-coordination-v1` proposal rather than assigning workers or creating another production queue. Existing original/canon and four action-source identities are inventoried with hashes in `existing-source-inventory.json`. The two real hover-wing drawings are reusable source studies, not a newly completed flight action.

Separate the **drawing clock** from the **actor path**. A wing-cycle track chooses immutable whole-bird drawn frames; a trajectory track places the actor root in world coordinates. Changing path speed, holding position or reversing a route must not restart the wing cycle or be counted as a new wing/body drawing. Conversely, interpolating or rotating a static sprite is a transform, not an intermediate wing phase. Current hover-up/down are whole-bird images; there is no separate body/wing layer asset to recombine independently.

The current source study proposes30Hz, one tick each for two hover drawings. That is15 displayed cycles/second, a stylized sampling cadence rather than a measured Anna wingbeat frequency. Review strobing and coherent body/bill position at actual presentation size before selecting cadence or requesting missing recovery/crossing wing drawings. Added flight-body pitches, braking/returning anatomy, feeding neck/bill and perch approach/fold/settle need actual source drawings where the existing images cannot support the action. No mandatory equal frame count is proposed.

`motion-contract-design.json` defines the proposed independent channels, explicit source mapping and support modes. It is **not** a canonical schema or executable Mac contract. The root/actor adapter remains with the main implementation owner. A source texture-review packet alone cannot assert flight-path binding. Use a separate source-to-action wrapper with exact atlas filenames/hashes, manifest filenames/hashes, source IDs/render IDs/rectangles, individual PNG hashes, clip IDs and30Hz schedules; never infer that every action clip is named`idle`.

Resolve the authoritative scale before mixing references. Canon uses96output, density1.2941176471, worldcanvas74.1818 and34world visible width. Earlier action studies use96output, density1.5, worldcanvas64 and~32.667world perched width. Those are separate declared presentations, not equivalent canvases. Preserve one individual scale within a cycle and make any coordinator-selected whole-call conversion explicit for image, pivot, bill and support anchors. Do not fit every new pose to its silhouette bounds or silently concatenate the two source sets.

Supported, airborne and flower-contact states have different constraints. Supported foot/perch root stays fixed until contact release and after first supported landing; airborne wing frames have no ground contacts. Nectar hover can hold a measured bill proxy at a flower using a declared actor-root offset, but positive alpha at the bill is not anatomical insertion or collision approval. Without actual feeding/landing source poses, those branches remain planned. Repositioning may reuse existing hover drawings on an authored path as a source study, with zero new drawing credit and no new biological claim.

One-shot action demonstrations must hold at their final root, with an explicit labeled Replay reset. The wing-cycle subtrack can loop while the root/path action remains one-shot. Clamp initial elapsed/tick values to valid bounds so a stale firstRAF timestamp cannot select an undefined pose. Verification must exercise both clocks independently and test the first-callback race, endpoint support, explicit clip selection, exact pixel mapping and actual-size wing/body/bill continuity.

This work stops at design. Coordinator selects the authoritative current Mac scale and next bounded Anna production assignment. No new image call is authorized by this document. No Library upload, global queue/bank, Git or application change is needed for this local technical handoff.
