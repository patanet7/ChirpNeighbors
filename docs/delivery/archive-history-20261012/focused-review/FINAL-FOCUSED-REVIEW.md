## Reviewed fixes

- **Read transactions:** Standalone lifecycle history and overview now use `BEGIN`; mutation entry points retain `BEGIN IMMEDIATE`. Nested calls reuse the caller's transaction and never independently commit it. `yard.snapshot` is a read, so the read path does not rely on upgrading a read transaction to a writer. Independent two-connection controls verified reading committed state while a writer holds its lock, refusal of a concurrent mutation, a consistent old snapshot when a writer commits between the yard and package reads, visibility of that commit in the following read, and a command overview seeing its own write.
- **Artifact index:** `pip_artifacts_owner_job(owner_id, job_id, created_at, version)` is an additive, nonunique startup index. It changes neither retained records nor owner/job filtering, uniqueness constraints, migration version or wire schemas. The focused query plan uses an exact owner/job search without a sorting scan. Reopening an old store missing the index and repeated startup preserve its rows. The provided old-v1 artifact/review and writer-lock tests cover the broader fixture upgrade case. Building the index on a large store can still take time; no production-scale migration timing is claimed.
- **Exact shared pin:** The ready-asset guard in `src/lib/client/contracts.ts` now compares all of `catalogPin` against the saved artwork, alongside species and the existing private animation pin. Matching shared releases remain accepted; changes to catalog key, release version or render digest are rejected for both read and command responses. Exact revoked/unavailable fallback still works. The existing absent catalog fields on private/legacy artwork remain compatible.
- **Initial page fallback:** `initialJobPage` validates its owner before catching a job-page read failure and returns only `{ jobs: [] }`, without fabricating a cursor or admitting a partial job. A healthy other owner's empty list retains real page metadata. The normal API job page still rejects corruption, the stored corrupt bytes remain unchanged, and an explicit later read recovers after the underlying metadata is repaired. Yard snapshot/assets and the existing strict SSR schema remain outside this fallback; invalid yard data is not silently accepted. The Jobs control visibly explains the missing initial list.
- **Deep cursor query:** For the validated integer cursor domain, `rowid <= min(watermark, before - 1)` is equivalent to the previous `rowid <= watermark AND rowid < before`; `before === null` retains the watermark alone. Subtracting one is safe because `before` is a positive safe integer. The empty watermark, `before = 1`, and maximum safe integer boundaries were checked. Signed cursor format, membership watermark, ownership, page size and response truncation logic remain unchanged.
- **Earlier guards:** The private read admission entry, byte-based input/artifact/aggregate checks and consistent lifecycle disabled predicates remain present. Earlier retention/cursor/concurrency controls were replayed against the final commit.
