# Historical engineering logs

These dated logs preserve original implementation decisions, source revisions, failures and scoped test results. They are historical evidence, not current setup instructions or a competing task list. Start at the [documentation index](../README.md), [task index](../delivery/product-behavior-and-ideas.md) or [verification ledger](../delivery/verification-ledger.md).

Do not create another per-session log by default. Update the existing canonical topic; add a concise dated release record only when it establishes a unique decision, source-bound result or unresolved limitation. Preserve failed and partial results instead of rewriting them as a pass.

Existing source logs remain available because their unique provenance has not all been superseded by canonical records. Search them with `rg` or inspect published Git history. The documentation cleanup does not modify their historical observations or any outside-repository research.
