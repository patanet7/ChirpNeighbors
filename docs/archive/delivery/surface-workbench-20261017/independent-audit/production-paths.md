## Actual end-to-end paths

**Owner yard:** `hooks.server.ts` verifies Better Auth account sessions or explicitly opted-in signed development sessions → `locals.identity.ownerId` → main server load / private API `requireOwner` → `YardRepository` → `yard_owners(owner_id PRIMARY KEY, schema_version, data)` in private `chirp.sqlite` → validated snapshot → Svelte view / engine inputs. [`repository.ts:155`](/Users/thomaspatane/GitHub/personal/birdsong-yard-sprites/src/lib/server/storage/repository.ts:155) queries by owner; mutations use `BEGIN IMMEDIATE` or savepoints, validate before writing and preserve immutable evidence. Owner is taken from verified locals, not a submitted owner field. `readCommand` requires same-origin JSON with body/time bounds. Hook-level session binding protects private API mutations from a stale document after account switching. Inspected code and passing isolated tests support actual tenant isolation; this reviewer found no demonstrated cross-tenant bypass.

**Owner recording:** `/recordings` → `/api/recordings` authenticated upload → `RecordingService` streaming WAV/header/hash validation → SQLite metadata/leases/receipts plus private filesystem bytes → owner/generation checks on playback and analysis permits → `/api/analysis` → bounded HTTP `POST {configured-origin}/v1/audio/analyze` forwarding only session cookies → Python re-verifies through BFF session/recording APIs → provider chunk inference → candidate response → BFF persists derived result → explicit `/api/analysis/confirm` → `AnalysisConfirmationService` atomically admits owner-reviewed observation and confirmation receipt. It does not auto-admit a candidate as a sighting. Deletion uses durable tombstones/outbox and prevents late inference from recreating deleted media.

**Audio model:** [`api.py:297`](/Users/thomaspatane/GitHub/personal/ChirpNeighbors/backend-inference/app/audio_pipeline/api.py:297) loads optional `app.audio_onnx.provider.ONNXProvider` only with `CHIRP_AUDIO_MODEL_MANIFEST`; otherwise `UnconfiguredModelProvider` blocks execution. `/readyz` reports auth/model configuration. [`audio_onnx/provider.py:1`](/Users/thomaspatane/GitHub/personal/ChirpNeighbors/backend-inference/app/audio_onnx/provider.py:1) implements local checksum-pinned CPU inference without bundled bird weights or automatic downloads. API tests inject `SyntheticFixtureProvider` and mock BFF transport; optional ONNX tests execute generated arithmetic graphs, not trained bird classification ([`test_audio_onnx.py:1`](/Users/thomaspatane/GitHub/personal/ChirpNeighbors/backend-inference/tests/optional/test_audio_onnx.py:1)). Provider execution infrastructure is materially present; biological accuracy/live configured model operation is not established by those tests.

**Owner asset:** `/api/image-files` → `ImageFileService.upload` → sharp decode → original/canonical/RGBA private files + owner-scoped immutable identity → explicit rights review → decoded source packaging with layout/clips → `JobRepository`/runner stage output and immutable artifact/review rows → `pinReviewedAnimation` → per-bird immutable artwork pin → `yardAssets` resolves exact reviewed manifest/source ancestry/digest → renderer. [`resolve.ts:137`](/Users/thomaspatane/GitHub/personal/birdsong-yard-sprites/src/lib/server/assets/resolve.ts:137) safely yields `unavailable` if missing/corrupt/unapproved, keeping the yard load usable. Legacy fixture SVG artwork is distinctly classified `legacy`; it is not silently treated as a reviewed render manifest.

**Preview admission:** `/candidate-yard` and `/garden-demo` share one server loader and read the same owner snapshot and reviewed assets, but are dev-only ([`candidate-yard/+page.server.ts:11`](/Users/thomaspatane/GitHub/personal/birdsong-yard-sprites/src/routes/candidate-yard/+page.server.ts:11)); `/art-lab` and `/asset-review` likewise read the real runtime and are dev-only. `/texture-review` server load returns only `{reviewOnly:true}`. Shared loading alone is not proof their client renderers exercise every production contract; scene/engine parity is handled by the separate renderer audit.
